# Problema actual

**Respuesta primero:** el reporte legacy está obsoleto y genera confusión entre recaudación en ruta y otros ingresos; GetNet además no tiene canal de captura definido.

{% hint style="success" %}
**Confirmado:** acordado en el levantamiento y en la maqueta del cliente.
{% endhint %}

## Situación

El levantamiento describe un reporte antiguo que debe **reemplazarse por completo** (Manu lo califica en términos coloquiales como desactualizado y mal armado). El objetivo es un reporte alineado con liquidación de recorrido, Pago Directo y cobro vendedor.

## Confusiones que el nuevo reporte debe evitar

| Tema                       | Qué pasa hoy                                                                                                                       | Fuente                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Ruta vs Pago Directo       | Efectivo y cheques de ruta se mezclan mentalmente con ingresos por Pago Directo                                                    | L §2, L §4                                           |
| GetNet                     | Existe la línea de ingreso POS/GetNet, pero **no está definido** de dónde sale el dato (cartola, planilla, declaración del chofer) | L §4, L §13, [P-01](../preguntas-pendientes.md#p-01) |
| Crédito vs control interno | El “cobro vendedor” (crédito) no debe confundirse con transferencias en validación vía control interno                             | L §3, L §4                                           |
